Web shop

Azure infrastructure diagram: Production. 6 elements in 5 groups, with 5 connections.

Groups and elements
- Users
- Front Door
- Production (Subscription)
  - rg-shop-prod (Resource group)
    - vnet-shop (Virtual network)
      - snet-apps (Subnet)
        - Web shop (App Service)
        - Orders API (Container App)
      - snet-data (Subnet)
        - Orders (SQL Database)
    - Secrets (Key Vault)

Connections
- Users send traffic to Front Door over HTTPS.
- Front Door sends traffic to Web shop.
- Web shop connects to Orders API (Private network: REST).
- Orders API connects to Orders (Private network: SQL) and signs in with Secrets (secrets).

Walkthrough
1. The web shop in production. One subscription, and nothing is public except the front door.
2. A customer opens the shop. Front Door terminates TLS and forwards to the web app.
3. Placing an order is a private REST call inside the virtual network.
4. Orders are stored: The Orders API writes to SQL over the data subnet.
  - Orders: No public endpoint
5. No secrets in code: The API reads its connection string from Key Vault with its managed identity.

Layers
Ways to look at this drawing by tag.
- Security: Only the front door is public; the API reads its secrets with its own identity. (tags security; 4 elements).
- Data: Orders live in SQL on the data subnet, reached only by the API. (tags data; 2 elements).
- Operations: What takes the traffic and runs our code, from the front door to the Orders API. (tags ops; 3 elements).

Key
- Solid sky line: Public traffic
- Dashed teal line: Private network
- Amber badge: Identity badge
