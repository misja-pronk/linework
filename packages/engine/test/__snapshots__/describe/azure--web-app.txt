Web shop on App Service

Azure infrastructure diagram: Northwind web shop · Front Door with WAF in front, no secrets in code, nothing else public. 9 elements in 5 groups, with 9 connections.

Groups and elements
- Customers (Internet)
- sub-shop-prod (Landing zone · Online)
  - rg-shop-edge (Global)
    - afd-shop-prod (Premium · WAF)
  - rg-shop-app (West Europe)
    - app-shop-web-prod (Storefront · public access off)
    - cae-shop-prod (Internal)
      - ca-shop-orders-prod (Orders API)
    - id-shop-web-prod (User-assigned)
    - id-shop-orders-prod (User-assigned)
  - rg-shop-data (West Europe)
    - stshopmediaprod (Product images)
    - sqldb-shop-prod (Entra-only · private)
    - kv-shop-prod (RBAC · private)

Connections
- Customers send traffic to afd-shop-prod over HTTPS.
- afd-shop-prod connects to app-shop-web-prod (Private network: Private Link) and connects to stshopmediaprod (Private network: /media).
- app-shop-web-prod connects to ca-shop-orders-prod (Private network: REST) and signs in with id-shop-web-prod.
- ca-shop-orders-prod connects to sqldb-shop-prod (Private network: TDS) and signs in with id-shop-orders-prod.
- id-shop-web-prod is Key Vault Secrets User on kv-shop-prod.
- id-shop-orders-prod is db_datareader · db_datawriter on sqldb-shop-prod.

Walkthrough
1. One public entry: The web shop in one subscription. Front Door is the only thing with a public address.
2. A customer opens the shop: Front Door terminates TLS, the WAF filters the request, and it reaches the storefront over Private Link.
3. Placing an order: The storefront calls the Orders API inside an internal Container Apps environment; the API writes to SQL.
4. No secrets in code: Each app runs as its own identity. Its roles on Key Vault or SQL replace passwords and connection strings.
