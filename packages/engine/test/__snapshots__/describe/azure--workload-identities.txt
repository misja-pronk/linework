Northwind workload identities

Azure infrastructure diagram: Which identity each workload signs in with, and which roles it holds where. 10 elements in 4 groups, with 8 connections.

Groups and elements
- GitHub (northwind/shop)
  - deploy.yml (GitHub Actions · environment prod)
- Northwind (Entra ID tenant)
  - github-prod (Federated credential · repo:northwind/shop)
  - app-shop-deploy (App registration)
  - app-shop-deploy (Service principal (enterprise app))
- sub-shop-prod (Subscription)
  - rg-shop-prod (Resource group)
    - app-shop-web (App Service · system-assigned identity)
    - kv-shop-prod (Key Vault)
    - func-shop-jobs (Function App)
    - id-shop-jobs (User-assigned managed identity)
    - stshopexports (Storage account)
- Microsoft Graph (Microsoft API)

Connections
- deploy.yml signs in with github-prod (OIDC token).
- github-prod connects to app-shop-deploy (App registration) (Management).
- app-shop-deploy (App registration) connects to app-shop-deploy (Service principal (enterprise app)) (Management: service principal).
- app-shop-deploy (Service principal (enterprise app)) is Contributor on rg-shop-prod.
- app-shop-web is Key Vault Secrets User on kv-shop-prod.
- func-shop-jobs signs in with id-shop-jobs (signs in as).
- id-shop-jobs is Storage Blob Data Contributor on stshopexports and signs in with Microsoft Graph (User.Read.All (application)).

Walkthrough
1. Three kinds: An app registration with its service principal for code outside Azure, and managed identities for code inside it. None of them has a secret to leak.
2. Deploying from GitHub: The workflow presents GitHub's OIDC token. The federated credential trusts only northwind/shop in environment prod, and Entra issues a token for the service principal.
  - github-prod: repo:northwind/shop:environment:prod
3. Pipeline, least privilege: The service principal is Contributor on one resource group, not on the subscription.
4. System-assigned: The web app's identity lives and dies with the app, and may only read secrets from its own vault.
5. User-assigned: The jobs run as an identity of their own, which can be shared and survives a redeploy. It writes exports and reads users through an application permission on Microsoft Graph.
  - Microsoft Graph: Needs admin consent

Key
- Dotted amber line: Identity
- Dotted line with ticks: Management
- Dashed indigo line with ticks: Role assignment
