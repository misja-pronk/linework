Checkout

Sequence diagram: Card payment with a payment provider, confirmed by webhook. 6 participants and 17 messages.

Participants
- Shopper
- Shop system
  - Storefront (Web app)
  - Orders API (Service)
  - Orders DB (Database)
  - order-events (Event stream)
- Stripe (Payments)

Message flow
In order, top to bottom.
- 1. Shopper calls Storefront: Place order.
- 2. Storefront calls Orders API: POST /orders.
- 3. Orders API does: Validate cart and prices.
- 4. Orders API calls Orders DB: INSERT order (pending).
- 5. Orders DB replies to Orders API: order id.
- Payment:
- 6. Orders API calls Stripe: Create payment intent.
- 7. Stripe replies to Orders API: client secret.
- 8. Orders API replies to Storefront: 201 Created.
- 9. Storefront sends to Stripe: Confirm card (3-D Secure in the browser).
- Note over Orders API and Stripe: The order stays pending until the webhook arrives, never on the browser's word
- Alternative: Payment succeeded
  - 10. Stripe sends to Orders API: webhook payment_intent.succeeded.
  - 11. Orders API calls Orders DB: UPDATE order SET status = paid.
  - 12. Orders DB replies to Orders API: ok.
  - 13. Orders API sends to order-events: OrderPaid.
- Else: Card declined
  - 14. Stripe sends to Orders API: webhook payment_failed.
  - 15. Orders API calls Orders DB: UPDATE order SET status = failed.
  - 16. Orders DB replies to Orders API: ok.
- 17. Storefront replies to Shopper: Order confirmation.

Key
- Arrow with a filled head: Call
- Dashed arrow: Reply
- Arrow with an open head: Async message
