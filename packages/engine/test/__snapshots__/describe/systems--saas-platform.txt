Booking platform

Architecture diagram. 10 elements in 2 groups, with 10 connections.

Groups and elements
- Guests (Users)
- Guest app (Mobile app)
- AWS eu-west-1 (Cloud)
  - Public edge (Zone)
    - CloudFront (CDN)
    - ALB (Load balancer)
  - EKS cluster
  - Data tier (Zone)
- Auth0 (Identity provider)
- Stripe (Payments)
- SendGrid (Email)
- Host dashboard (Web app)

Connections
- Guests connect to Guest app.
- Guest app calls CloudFront over HTTPS and connects to Auth0 (Supporting: OIDC).
- CloudFront calls ALB.
- ALB calls EKS cluster.
- EKS cluster sends data to Data tier, calls Stripe (charge) and calls SendGrid.
- Data tier sends messages to EKS cluster.
- Host dashboard calls CloudFront over HTTPS.

Layers
Ways to look at this drawing by tag.
- Phase 1: Guests book through the app; one service, one database. (tags phase-1; 7 elements).
- Phase 2: Search, billing and notifications join, around an event stream. (tags phase-2; 7 elements).
- Data stores (tags data; 1 element).

Key
- Solid line with beads: Connection
- Solid blue line: Request
- Dashed amber line: Async message
- Solid violet line with ticks: Data flow
- Dotted line: Supporting
