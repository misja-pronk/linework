Release to production

Process diagram: Every merge is built and staged by the pipeline; a person decides what reaches customers. 15 elements in 3 lanes, with 15 connections.

Lanes and steps
- Developer (lane)
  - Start event
  - Merge to main
  - Fix the build
- Pipeline (lane)
  - Build and test
  - Tests green? (decision decision)
  - Deploy to staging
  - Smoke tests
  - Deploy to production
  - Healthy? (decision decision)
  - Released (end event)
  - Roll back
  - Release failed (error end event)
- Release manager (lane)
  - Review release (change notes and test report)
  - Approved? (decision decision)
  - Release held (end event)

Main path
1. Start event
2. Merge to main
3. Build and test
4. Tests green?
5. Deploy to staging: Tests green? yes
6. Smoke tests
7. Review release
8. Approved?
9. Deploy to production: Approved? yes
10. Healthy?
11. Released: Healthy? yes

Connections
- Start event leads to Merge to main.
- Merge to main leads to Build and test.
- Build and test leads to Tests green?
- Tests green? leads to Deploy to staging (yes) and leads to Fix the build (no).
- Deploy to staging leads to Smoke tests.
- Fix the build leads to Merge to main.
- Smoke tests leads to Review release.
- Review release leads to Approved?
- Approved? leads to Deploy to production (yes) and leads to Release held (no).
- Deploy to production leads to Healthy?
- Healthy? leads to Released (yes) and leads to Roll back (no).
- Roll back leads to Release failed.

Key
- Solid line, thick: Happy path
- Solid line: Other paths
