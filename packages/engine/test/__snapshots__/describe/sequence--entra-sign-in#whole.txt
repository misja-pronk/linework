Sign in with Entra ID

Sequence, whole sequence: Northwind Orders portal: authorization code flow with PKCE, Conditional Access, and an API that checks every token. 4 participants and 13 messages.

Participants
- Employee
- Orders portal (SPA in the browser)
- Microsoft Entra ID (Identity provider)
- Orders API

Message flow
In order, top to bottom.
- Sign in:
- 1. Employee calls Orders portal: Open the portal.
- 2. Orders portal does: Make code_verifier and challenge.
- 3. Orders portal calls Microsoft Entra ID: /authorize: scope, code_challenge.
- 4. Employee calls Microsoft Entra ID: Sign in with password or passkey.
- 5. Microsoft Entra ID does: Evaluate Conditional Access.
- Optional: Policy requires MFA
  - 6. Microsoft Entra ID calls Employee: Approve in Authenticator (number match).
  - 7. Employee calls Microsoft Entra ID: Approved.
- 8. Microsoft Entra ID replies to Orders portal: Redirect to the portal with code and state.
- Tokens and the API:
- 9. Orders portal calls Microsoft Entra ID: /token: code, code_verifier.
- 10. Microsoft Entra ID replies to Orders portal: ID token, access token, refresh token.
- 11. Orders portal calls Orders API: GET /orders with the access token.
- 12. Orders API does: Validate signature, iss, aud, exp, scp.
- 13. Orders API replies to Orders portal: 200 OK, orders.

Key
- Arrow with a filled head: Call
- Dashed arrow: Reply
